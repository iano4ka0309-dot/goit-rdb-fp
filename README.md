# Прогнозування відтоку клієнтів телеком-компанії (Customer Churn Prediction)

Фінальний проєкт курсу Machine Learning NEO (GoIT). Завдання — побудувати модель бінарної класифікації, яка передбачає, чи піде клієнт від оператора зв'язку, на основі 230 анонімізованих ознак (190 числових, 40 категоріальних) з сильним дисбалансом класів (~87% / 13%).

**Фінальний результат:** balanced accuracy ≈ 0.92 на публічному лідерборді Kaggle.

## Структура даних

- `final_proj_data.csv` — навчальний набір, 10 000 рядків, є цільова змінна `y`
- `final_proj_test.csv` — валідаційний набір, 2 500 рядків, без `y`
- `submission.csv` — фінальний файл з прогнозами у форматі `index,y`

## Хід роботи

### 1. Розвідувальний аналіз (EDA)

- Видалено 18 колонок, які були порожні на 100%.
- Виявлено дисбаланс класів: ~87% клієнтів залишились, ~13% пішли. Обрано метрику balanced accuracy — саме тому, що звичайна accuracy була б оманливою при такому дисбалансі (наївна модель "завжди 0" дає 87% accuracy, але лише 43.5% balanced accuracy).
- Серед 190 числових ознак знайдено 131 колонку з екстремально високим відсотком пропусків (95%+).

### 2. Ключова знахідка: структуровані пропуски

Дослідивши пропуски глибше, виявлено, що вони **не випадкові**: 131 розріджена колонка групується у 13 наборів, де для кожного клієнта пропуски всередині набору йдуть "все або нічого" — або заповнені всі ознаки групи одразу, або жодної. Це знайдено через побудову графа зв'язків (кореляція матриць пропусків, `networkx.connected_components`).

Замість 131 розрідженої колонки створено 13 компактних бінарних індикаторів ("чи застосовна ця група ознак до клієнта") — це дало перший суттєвий приріст метрики.

### 3. Категоріальні ознаки

38 категоріальних колонок розділено за кількістю унікальних значень:
- 4 колонки з єдиним значенням (крім NaN) → перетворені на бінарні індикатори
- 7 колонок з 3–4 категоріями → One-Hot Encoding
- Решта (сотні–тисячі унікальних значень) → спершу Frequency Encoding, згодом замінено на **K-Fold Target Encoding** для усунення витоку даних (пряме кодування середнім `y` без крос-валідації давало підозріло ідеальний результат ~0.99 на локальній перевірці — явна ознака витоку).

### 4. Побудова моделей і порівняння

Протестовано декілька алгоритмів:

| Модель | Підхід | Результат (Kaggle) |
|---|---|---|
| CatBoost (baseline) | без обробки категорій, тільки заповнення NaN | 0.771 |
| LightGBM | + обробка категорій, class_weight='balanced', тюнінг гіперпараметрів | 0.895 |
| Random Forest | + PCA для зменшення розмірності | 0.55–0.63 (гірше за бустинг) |
| XGBoost | той самий пайплайн ознак | 0.872 |
| Ансамбль LightGBM+CatBoost | усереднення ймовірностей | гірше за одиночну сильнішу модель |
| **CatBoost, спрощений пайплайн** | без ручних підкластерів, вбудована обробка категорій (`cat_features`) | **0.92** |

### 5. Важливий урок: спрощення переміг ускладнення

Спочатку для кожної з 13 груп ознак шукались "підкластери" (сильно скорельовані підгрупи всередині групи, об'єднані через нормалізацію + середнє). Це виглядало логічним покращенням, але:
- Feature Importance показав, що модель майже не використовує ці підкластери-ознаки.
- Прибирання підкластерів і довіра до **вбудованого** механізму обробки категорій CatBoost (замість ручного Target Encoding) дало кращий результат, ніж уся ручна інженерія ознак.

Висновок: сучасні градієнтні бустинги (CatBoost, LightGBM) вміють самі ефективно обробляти категорії та пропуски — надмірна ручна обробка іноді "заважає" моделі, а не допомагає.

### 6. Валідація методом

Одноразовий `train_test_split` виявився ненадійним індикатором реального результату — локальні покращення (до 0.92+ на одному розбитті) регулярно **не підтверджувалися** на Kaggle. Перехід на **5-fold стратифіковану крос-валідацію** дав набагато чесніші, стабільніші оцінки, які значно ближче до реального результату на новому наборі даних.

### 7. Підбір гіперпараметрів

Ручний перебір (`depth`, `iterations`, `learning_rate`, `l2_leaf_reg`, `random_strength`) комбінувався із систематичним пошуком (`RandomizedSearchCV` з 5-fold CV) для фінального налаштування моделі.

## Що НЕ спрацювало (і чому це теж корисно знати)

- **SMOTE** — гірше за `class_weight='balanced'`: ймовірно, через велику кількість ознак синтетичні приклади виходили нереалістичними.
- **PCA** — знищував корисний сигнал, тому що орієнтувався на загальну варіацію даних, а не на зв'язок з `y`.
- **Прямий (без K-Fold) Target Encoding** — витік даних, локальна метрика ~0.99, нереалістично висока.
- **Ансамблювання різних за силою моделей** — слабша модель "розмиває" сильнішу.
- **Ручні підкластери ознак** — не давали приросту порівняно з довірою до вбудованих механізмів CatBoost.
